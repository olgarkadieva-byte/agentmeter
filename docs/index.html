Free and open source · AgentMeter

Test your AI agent before it ships.

Does each new version finish more tasks, call the right tools, stay inside its permissions, and do it at an acceptable cost and speed? AgentMeter scores every version and gives a release verdict: Ship Hold or Block.

View the code on GitHub

Your data never leaves this page: all calculations run in your browser and nothing is uploaded.

Use your own agent runs

Log your agent's runs in the data contract format (the Python Recorder does it in a few lines), then choose the files below. You can select them all at once.

Runs: one line per attempt at a task, with the tool calls made. Task suite: what a correct run must say and which tools it must or must not use. Policy (optional): which tools are allowed, limits, and when a person must approve.

    What it measures

    Task success, honestly

    Each run is graded against the task's expected answer and required tools. Ranges are clustered by task, because repeated tries at the same task are not independent.

    Reliability

    pass^k is the share of tasks the agent gets right on every attempt. Users notice an agent that works only some of the time.

    Permissions

    Every tool call is checked against your policy: unknown tools, hard limits, and actions that need a person's approval. The same rules can block calls at runtime.

    Cost and speed

    Cost per successful task, not per call, and p95 latency, because the slowest answers are the ones people remember.

    Works with real agents

    Any model

    A built-in agent loop for Claude and OpenAI-compatible models, with step limits, timeouts and the permission guard on every tool call. Or record runs from your own framework.

    MCP tools

    Use the tools of any MCP server in an evaluation, or serve your tools over MCP. Each call's result is recorded, so later versions can be replayed against the same outputs.

    Open-ended answers

    Add a rubric to a task and a model judge grades each answer, with a one-sentence reason you can spot-check. Unjudged runs hold the release.

    Experiments in one command

    agentmeter run runs a real model on the 60 demo tasks, with memory on or off, so you can measure what a change does before you ship it.

    How the release gate decides

    VerdictWhen
    ShipNo policy violations, success is no worse than the baseline beyond your margin, and cost per success and p95 latency stay within budget.
    HoldCost or latency is over budget, a meaningful drop in success can't be ruled out yet, or open-ended answers haven't been judged.
    BlockAny policy violation, or success is significantly lower than the baseline.

    Run it in CI

    pip install git+https://github.com/olgarkadieva-byte/agentmeter.git
agentmeter gate eval/ --baseline prod --candidate candidate

    The command exits with 0 on Ship and 1 otherwise, so a regression fails the build. A ready-made GitHub Actions workflow is in the repo.
